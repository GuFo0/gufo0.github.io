3. Cryptographic Discussion: ECDLP vs. Hash Functions

1. Which observed properties are meaningful for a Cryptographic One-Way Function (OWF)?
• Hardness of Inversion (Pre-image Resistance): In the forward direction, scalar multiplication Q = kG takes logarithmic time O(log k) using double-and-add. Inverting it to find k given Q requires solving the Discrete Log Problem, which takes O(√N) steps. On Ethereum's secp256k1 curve (N ≈ 2256), inversion requires ≈ 2128 operations, which is computationally infeasible.
• Zero Linear Correlation: Notice above that r(k, x) = 0.0000 identically. Knowing k provides zero linear prediction of x, preventing simple regression attacks.

2. Which properties are specifically associated with Cryptographic Hash Functions?
• Strict Avalanche Criterion (SAC): True hash functions (like Keccak-256) require every input bit flip to trigger an independent, unpredictable 50% change across all output bits. While Chart 2 shows an average bit flip of ~46%, ECC exhibits systematic structural flaws: at 4G → 5G, the x-coordinate remains strictly identical (x=12) because 5G = -4G in group order 9. A hash function must never preserve such reflection symmetries.
• Non-Algebraic Structure: Hash functions are specifically engineered to eliminate any algebraic relations. In contrast, ECC multiplication is strictly homomorphic: (a + b)G = aG + bG. This homomorphism is the foundation of digital signatures (ECDSA/Schnorr) and ZK-proofs, but would represent a catastrophic flaw in a cryptographic hash function.
